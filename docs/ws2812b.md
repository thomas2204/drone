# WS2812B strip on PA10

The STM32H743 project now compiles the Apache-2.0
[ws2812 DMA library](https://github.com/simonbln/stm32-ws2812-dma-chained)
and an H7 adapter, `Core/Inc/led_strip.h`.

Use PA10 (`WS2812_DATA`, TIM1_CH3) for DIN. The existing CubeMX setup uses
DMA1_Stream3, normal mode, halfword transfers, and a 64 MHz timer clock with
prescaler 0 / period 79, producing 800 kHz. No CubeMX changes are needed.

The adapter provides up to 128 LEDs, GRB transmission, a 320 us reset low,
and nonblocking transfers. Its aligned DMA buffer uses the existing RAM_D2
linker section and is explicitly initialized and cleaned before DMA reads it.
The clock/configuration check intentionally rejects changes to this timer
setup; update the adapter timing if changing the clock tree.

## Example

The actual strip LED count is still needed. This example uses **8 only as an
example**. Add the include in a USER CODE Includes block and initialization
in main.c's USER CODE BEGIN 2 block (after MX_TIM1_Init):

```c
#include "led_strip.h"

/* Replace 8 with your actual LED count. */
if (LED_Strip_Init(8) != HAL_OK ||
    LED_Strip_Fill(0, 255, 0, 16) != HAL_OK ||
    LED_Strip_Show() != HAL_OK) {
    Error_Handler();
}
```

This sends dim green once. No automatic lighting example is enabled in the
firmware until the LED count is chosen. No new RTOS task is required.

To change one LED later, from one owning task:

```c
if (!LED_Strip_IsBusy()) {
    if (LED_Strip_Set(0, 255, 0, 0, 16) == HAL_OK) {
        HAL_StatusTypeDef status = LED_Strip_Show();
        /* Handle status according to your application's error policy. */
        (void)status;
    }
}
```

Set/Fill edit the buffered frame; Show starts transmission. Init/Set/Fill/Show
return HAL_BUSY while sending. Brightness is 0..255 and the upstream encoder
scales each channel by brightness / 256. Use one task for the API; it is not
thread safe. The adapter owns HAL_TIM_PWM_PulseFinishedCallback and
HAL_TIM_ErrorCallback; merge callback handling if adding other PWM DMA users.
An asynchronous DMA error stops output and clears busy; the application may
resend the frame. Completion/busy clearing alone does not report success.

## Wiring

- Connect PA10 through a suitable 3.3 V to 5 V logic buffer to the strip DIN.
- Power the strip from a regulated supply matching its rated voltage, commonly
  5 V; join strip and controller grounds. Do not use the GPIO as strip power.
- Size the supply and wiring for the actual strip current. Follow the strip's
  instructions for input resistor and supply decoupling.

The MCU pin name PA10 is used in software. Verify physical package pin 123
against your board schematic before wiring.

Build with `cmake --preset Debug` then `cmake --build --preset Debug`.
Compilation does not verify physical wiring or the LED waveform; those still
need a powered hardware check.
